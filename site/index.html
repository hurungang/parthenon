Platform Design

High-Level Architecture

Parthenon is composed of three strictly isolated backend services and a dual-identity model, connected through a permissions framework built around Skills, SOPs, and Agent Roles.

Plug
SOP / Skill-Driven MCP Integration
  • Skills wrap one or more MCP tool calls into a named, permissionable unit
  • SOPs compose multiple Skills with sequencing logic and support agent-to-agent delegation
  • Each MCP server is registered with a unique slug; all tools sync under that namespace
  • Permissions are granted at the tool level through skills and roles
Shield
Security & Permission Control
  • Agent Roles are permission sets granting access to specific SOPs and Skills
  • Roles resolve to a complete deterministic set of allowed MCP tools at runtime
  • Agent identities are first-class OIDC principals in a dedicated agent realm
  • Agents never hold identity tokens directly; tokens are injected per tool call
Gear
Three-Service Isolation
  • Control Center is the sole database owner and policy authority
  • Communication Hub brokers UI-agent and agent-agent messaging
  • Agent Runtime executes agents only and has no direct database access
  • Cross-service calls use certificate-based mTLS with isolated credentials
ID
Dual Identity Support
  • User Realm for human OIDC accounts and standard OAuth2 login
  • Agent Realm for AI agent identities with encrypted credential storage
  • Agent Types pair identity, role, model, instruction, and I/O mode
  • Each run validates identity-role assignment before execution starts

Trust & Compliance

Security Deep Dive

Parthenon enforces security at every boundary from tool-level permissions to certificate-based service identity and strict token isolation.

Lock
Tool-Level Permission Control

Permissions are granted at individual MCP tool level. Agent Roles define which Skills an agent can invoke, and each execution resolves a deterministic allow-list of tools.

SOP to Skill to Tool
Cert
mTLS Certificate Authentication

Agent Runtime receives short-lived agent-instance certificates while internal services use longer-lived service certificates. All inter-service calls are mutually authenticated via mTLS.

24h agent-instance / 30d service
Token
Token Isolation

Agent Runtime never stores raw identity tokens. Communication Hub injects scoped tokens just in time per tool call, and agent certificates are blocked from internal management APIs.

Just-in-time token injection

Step-by-Step Walkthroughs

Demo Walkthroughs

Follow these guided flows to understand how operators configure and run AI agents on Parthenon.

  1. 1

    Register the MCP Server

    In Control Center MCP Hub, click Add MCP Server, provide a unique slug, endpoint URL, and credentials encrypted at rest.

  2. 2

    Sync Tools

    Sync the remote tool manifest and confirm imported tools appear under the server namespace.

  3. 3

    Configure Sessions

    Create named MCP sessions and bind identity context per session for controlled tool use.

  4. 4

    Test Connectivity

    Run connection checks and manifest validation to confirm the server is ready for Skills.

  1. 1

    Define Skill

    Create a Skill and map exactly which MCP tools it can invoke as a reusable governed unit.

  2. 2

    Compose SOP

    Build a SOP by sequencing Skills with optional branching and delegation rules.

  3. 3

    Review Tool Allow-List

    Confirm the transitive tool set resolved from the SOP matches security intent.

  4. 4

    Test SOP

    Execute a controlled dry run and inspect order, intermediate outputs, and tool usage.

  1. 1

    Create Role

    Create an Agent Role that will become the governance boundary for tool access.

  2. 2

    Assign SOPs and Skills

    Attach approved SOPs and direct Skills to the role to define intended capabilities.

  3. 3

    Bind Agent Identity

    Associate agent-realm identities to the role through the identity-role assignment panel.

  4. 4

    Validate Allow-List

    Inspect the computed transitive MCP tool allow-list before production activation.

Agent Types define identity, role, model configuration, system instruction, and I/O mode. After saving, operators can trigger non-conversational jobs or conversational sessions.

  1. 1

  2. 2

  3. 3

    Collect Structured Result
