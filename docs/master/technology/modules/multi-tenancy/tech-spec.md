# Multi-Tenancy — Technical Spec

## Technical Overview

Multi-tenancy is implemented as an opt-in platform mode controlled by a `multi_tenancy_enabled` row in the `PlatformSetting` entity (default false). When off, every multi-tenant code path is inert and the product behaves as a single-tenant deployment; since the Phase 11 root-tenant model, even switch-OFF deployments operate against an implicit **root tenant** (`Root`/`root`, flagged `is_system_tenant` — the design's `is_root_tenant` rename was recorded but NOT applied; the existing column is retained). When on, Control Center resolves the tenant exactly once per request (workspace address subdomain, tenant header, or explicit slug) into an immutable `TenantContext`, validates that the JWT's tenant claim matches, and enforces row-level tenant scoping at the database gateway — Control Center remains the only service that touches PostgreSQL. The context is propagated read-only to Agent Runtime and Communication Hub as HMAC-signed headers on the existing mTLS channels; neither service can widen it.

**Tenant resolution + candidates.** `TenantResolutionMiddleware` (registered in `create_app()` after `JWTAuthMiddleware` so it executes first) resolves slug → active tenant and is fail-closed in multi-tenant mode: public health/setup/auth paths, method-aware GET-only login probes (`BYPASS_GET_PATHS`), internal service-to-service paths, and the platform admin surface are bypassed; everything else requires a resolvable tenant. On the frontend, sign-in tenant binding is candidate-based: the OIDC callback's sources (token claim → session → remembered hint → memo) are *candidates only*, each verified through public tenant discovery before binding, with an apiClient self-heal that clears a fail-closed unknown-slug binding. The login page offers an AWS-style "find your workspace" address flow, a `?workspace=` deep link, and a remembered-workspace hint (always re-verified — never an access decision).

**Containment (Phase 11).** Permission evaluation is contained to the session tenant: with a resolved tenant, `PermissionEngine` collects ONLY roles with `Role.tenant_id == tenant` (global tenant-less role collection was removed; legacy globals were re-homed into the root tenant's role space by migration `b8e4f2a6c9d1`). `platform::*` checks therefore evaluate the session tenant's roles — platform administration lives in the root tenant's `Platform Admin` role (seeded + assigned to root `platform_admin` members), the no-membership gate and root blanket grant apply to customer tenants, and the super-admin bypass is unchanged. The earlier FIX-20260930-235927 platform-membership gate helper `_system_tenant_platform_admin` was removed by this model.

**Scoping choke point.** `apply_tenant_scope` on the `get_db` session dependency rewrites SELECT/UPDATE/DELETE, auto-stamps INSERTs, audits cross-tenant misses, and verifies signed headers on internal traffic. Identity-plane statements (PlatformUser-by-sub, JIT provisioning upserts, operator Identity-by-subject) opt out via the statement-scoped `execute_unscoped` exemption; data-plane queries keep the full scope, and an authenticated user without an ACTIVE membership in the resolved tenant receives the structured `no_access_to_workspace` 403 — never a re-authentication prompt.

**Per-tenant / shared / root OIDC.** The global provider registry is a per-tenant cache keyed by (tenant, scope). Resolution order for both tenant-scoped and tenant-less lookups: own `(tenant, scope)` slot → SHARED tenant-less `(None, scope)` slot → ROOT tenant's slot (the adopted platform provider; internals named `_root_tenant_id` after Phase 11). A tenant-less `IdentityProviderConfig` IS the shared provider; one provider can serve the platform and every tenant; none of the three slots fails closed. On validation the `tenant` claim (slug) is injected from the resolved login context (`_inject_tenant_claim`), never from the request's `X-Tenant` header; `_check_tenant_claim` mismatch rejection is unchanged.

**JIT default tenant role.** `IdentityProviderConfig.default_tenant_role` (nullable enum over four seeded presets; migration `a1f2c3d4e5b6`) enables JIT admission: on first OIDC sign-in with a resolved tenant, a registry-token provider carrying a default role, and no active membership, `jit_membership_with_default_role` creates an ACTIVE non-root membership and assigns the tenant's preset role — idempotent, audited as `self_serve_registration`. The four presets (`DefaultTenantRolePreset`) are seeded per tenant by `TenantService.create`, self-healed at startup by `sweep_missing_tenant_default_roles`, and validated against the resource-type manifest at seed time.

**Licensing & quotas.** `TenantLicense` (free / team / enterprise with max_users, max_agent_types, monthly_agent_executions; supersede semantics, latest active wins, history retained) governs growth; an unlicensed tenant falls back to built-in free-tier defaults owned by `TenantLicensingService`. Quotas are enforced at exactly three CC decision points — user invitation/creation, agent type creation, and execution submission (the scheduler re-consults at dispatch time) — with refusal always at CC before any dispatch to CH/AR and every block returning the structured `QuotaBlockedPayload` (HTTP 403, recorded decision). `monthly_executions` uses a maintained `TenantQuotaUsage` calendar-month bucket counter (never refunded); users and agent types are derived live.

**Registration.** Self-serve signup is account-first and public: `POST /api/v1/auth/register` atomically creates the `PlatformUser` (bcrypt password credential, platform-issued `sub`, outside the per-tenant OIDC registry), the tenant, and the owner's root membership — switch-gated and throttled, with duplicate-email, one-owned-tenant-per-user, and slug validation before any write. Platform-issued accounts sign back in via `POST /api/v1/auth/login-password`. This supersedes and replaces the removed authenticated `register-organization` endpoint.

**Tenant root protection.** The root membership (`is_root`, exactly one per tenant, partial unique index) is immutable — every actor's mutation against it is rejected by `guard_non_root_membership` and audited as `root_protection_rejected`. The root holds ALL tenant permissions (blanket grant for every module except `platform::*`), and only the root may edit the tenant alias; the slug (address) is immutable.

**Other surfaces.** Platform admin APIs under `backend/app/api/v1/platform/` expose tenant metadata, settings, licensing, and cross-tenant audit — never tenant business data; the tenant self-service router exposes the tenant's own settings, members, invitations, and usage. AR/CH bind the signed tenant context on execution, routing, MCP sessions, and API keys. The frontend ships a platform admin console (`/platform/*`, gated by the `usePlatformAccess`/`PlatformAdminRoute` permission probe — never by `multiTenancyEnabled` alone), a tenant workspace (tenant admin pages, license/usage panel, quota-blocked alerts), and public sign-up/sign-in surfaces. New `platform::*` / `tenant::*` resource types are registered in both backend and frontend manifests. New audit event types cover registration, root protection, license changes, and quota exhaustion.

## Component Breakdown

- **Tenancy platform switch** — `PlatformSetting` + `PlatformSettingsService`: cached key/value store; the switch row is seeded false at startup with write-through invalidation; every feature branches on the cached read.
- **Tenant Context** — immutable per-request `TenantContext` (+ `TENANT_UNSET` sentinel and accessors) on `request.state`; `is_tenancy_enabled` is the Phase 11 authority for "tenancy features apply".
- **Tenant Resolution Service + Middleware** — slug/header → active tenant, fail-closed, short-TTL cache; middleware binds the context (root-tenant default context when the switch is off), bypasses safe public/GET probe paths, and audits rejections.
- **Signed propagation** — `build_tenant_signature_headers` / `verify_tenant_signature_headers` (`X-Internal-Tenant-*`): CC signs on internal clients; AR (`ControlCenterCertificateMiddleware`) and CH (`ControlPlaneMiddleware`) verify but never sign; AR/CH forwarders re-emit, never re-sign.
- **Row-level scoping** — `apply_tenant_scope` + `get_db` choke point with INSERT stamping, closure-factory criteria (lambda-SQL cache safe), miss auditing, `execute_unscoped` identity-plane exemption, and `flush_scope_miss_audits`.
- **Tenant-aware permission engine** — tenant-scoped role collection/policy lookup; Phase 11 containment (no global roles); root blanket grant; `no_access_to_workspace` no-membership gate; super-admin bypass.
- **Per-tenant OIDC registry** — (tenant, scope) cache with own → shared → root resolution; `_inject_tenant_claim`; per-tenant scope uniqueness in `OIDCConfigService`.
- **JIT default tenant role** — `DefaultTenantRole` presets, seeding, sweep, and the `_maybe_jit_default_role` admission hook in `JWTAuthMiddleware`.
- **Tenant lifecycle services** — `TenantService`, `TenantProvisioningService`, `TenantAdoptionService` (root-tenant adoption/re-homing), `TenantAuditService`, and root-tenant helpers in `root_tenant.py`.
- **Tenant Registration Service** — atomic account-first signup (PlatformUser + Tenant + root membership), plus `platform_account_auth_service` (bcrypt credentials, platform JWTs) and the `_try_platform_account_token` auth tier.
- **Licensing Service** — `TenantLicense` ownership, supersede semantics, free-tier defaults, effective-limits resolution.
- **Quota Service + error contract** — three quota checks + counter maintenance; `QuotaExceededError` / `QuotaBlockedPayload` mapped to a single HTTP 403.
- **Tenant root protection** — `guard_non_root_membership` shared by tenant + platform mutation paths.
- **Platform Admin APIs / tenant self-service router** — platform tenants/settings/audit + license endpoints; tenant settings/onboarding/members/invitations/usage.
- **Agent Runtime (tenant-bound execution)** — signed-header verification, context binding on execute/resume/terminate/intervene, forwarding data client.
- **Communication Hub (tenant-bound routing)** — control-plane + API-key middleware tenant binding; scoped session dispatch, A2A, MCP server/tools.
- **Frontend** — platform admin console, tenant workspace (settings/onboarding/members), public sign-up + workspace-address sign-in, OIDC callback verified binding, apiClient self-heal, license/usage and quota-blocked components.
- **Observability & audit** — `TenantAuditEvent` persistence and `set_tenant_span_attributes` tenant attribution on spans/logs in all three services.
