# Parthenon Enterprise AI Harness — Product Documentation

Welcome to the master product documentation for the Parthenon Enterprise AI Harness. This index provides an overview of all core platform features, each with a dedicated specification document.

Parthenon is self-serve SaaS-capable: a visitor can sign up with an email and password and instantly receive their own tenant workspace, with license-based tiers (free / team / enterprise) governing growth. The platform itself operates as the **root tenant** (workspace `root`), where platform staff hold platform roles. The tenancy mode defaults to single-tenant — the deployment behaves as the root tenant's workspace — with multi-tenancy available as an opt-in switch.


## Feature Index

- **Multi-Tenancy** — Opt-in (default-off) multi-tenancy with the root tenant as the platform: self-serve registration creating a tenant root user, unified workspace-address sign-in, strict tenant-contained permissions (wildcards included), tenant admin module, strictly per-tenant identity providers (no shared provider or fallback chain) with JIT default role, license tiers with user/agent-type/monthly-execution quotas, and tenant lifecycle with isolation guarantees. See [Strict Tenant Isolation](features/strict-tenant-isolation.md) and [Multi-Tenancy](features/multi-tenancy.md).
- **Foundation Platform** — Roles, permissions, provider-agnostic OIDC integration (any OIDC-compliant provider), independent user and agent identity providers, built-in super admin with enable/disable lifecycle, database-backed identity configuration, OIDC provider testing, setup wizard, Web UI shell, and operational dashboard. See [Foundation Platform](features/foundation-platform.md).
- **Dashboard Metrics** — Real-time stat cards, time-sensitive metrics with date range picker, and permission-aware widgets for platform health overview. See [Dashboard Metrics](features/dashboard-metrics.md).
- **MCP Hub** — Server registration, tool sync, session management, credential binding, proxy, and a "needs re-authentication" session state for credentials that can no longer be refreshed automatically, with in-place recovery. See [MCP Hub](features/mcp-hub.md).
- **MCP Demo App** — Minimal MCP application for validating agent identity authentication and tool registration (reference implementation), now with two demo modes: identity/greeting tools and a fictional airline booking scenario (search, book, payment link, status, check-in, seat, cancel) over in-memory seed data, showcasing confirm-before-write, permission denial, a scripted zero-model check-in, and both chat-UI and third-party client surfaces. See [Airline Booking Demo walkthrough](../reference/airline-booking-demo-walkthrough.md) and [MCP Demo App](features/mcp-demo-app.md).
- **Skill Management** — Skill definition, explicit MCP tool bindings (a skill can only invoke its bound tools), bound-tool visibility, permission assignment, and demo skills (including a restricted role variant for demonstrating access denial) for the airline booking scenario. See [Skill Management](features/skill-management.md)
- **SOP Management** — SOP composition, step sequencing, agent-to-agent delegation, AI-assisted workflow authoring, and bounded delegation guardrails (cyclic-delegation prevention, depth limits, Default SOP fallback). See [SOP Management](features/sop-management.md).
- **Agent Management** — Agent types, identity, instance lifecycle, and max-instance enforcement, with Run and Optimize as distinct actions, explicit Generate/Regenerate plan, a requires-fix alert with auto-recorded feedback, model-not-configured guidance, and a "Talk to optimizer" conversation on the Optimized Plan tab (scoped, default-collapsed session summary, script-based live-test approval card, automatic refresh). See [Agent Management](features/agent-management.md).
- **Agent Management Panel** — Unified panel to create, inspect, and edit agents end-to-end: header create/delete, all editing in the right-hand property bar, inline create-and-assign of roles, identities, skills, SOPs, data types, and model configurations via reusable dialogs, searchable/paginated resource picker, draft-until-save editing with a pending-changes tray and discard, and a live agent topology featuring the Communication Hub with fullscreen and zoom
- **Agent Types** — Per-Agent-Type execution guardrail profiles and bounded policy controls, with completeness expectations (working model + identity or role + bindings), full conversational configuration at UI parity, an execution-only model (plan authoring and optimization use the workspace authoring model), no plan generation for conversational types, an optimization-mode conversation that creates no new agent type/role/permission, and protection for system-provided agent types. See [Agent Types](features/agent-types.md).
- **Agent Identity** — OIDC agent-realm sign-in, encrypted token storage and automatic refresh, and identity-to-role assignment. See [Agent Identity](features/agent-identity.md).
- **Agent Execution** — Asynchronous agent session lifecycle from submission through completion, powered by the deep agent framework, including a durable human-in-the-loop intervention lifecycle (awaiting human input → resumed) that survives restarts and instance hand-offs with exactly-once application of confirmed changes, and operator-approved single live optimization script runs attributed to the agent and approver. See [Agent Execution](features/agent-execution.md).
- **Token Expiry Alerting** — Dashboard indicators and topology badges for expired/expiring agent identity and MCP session credentials, warning-to-remediation deep links, and pre-execution token validation that blocks runs with expired credentials. See [Token Expiry Alerting](features/token-expiry-alerting.md)
- **Agent Plan Mode** — Explicit, operator-initiated plan generation and preview for agent types, authored by the workspace's approved authoring model (never the agent's runtime model), with no-plan / out-of-date / model-not-configured states, automatic refresh after generation, and no plan generation for conversational agent types. See [Agent Plan Mode](features/agent-plan-mode.md).
- **Software 3.0 Agent Framework** — Workflow compilation: agents generate, verify, and promote deterministic bridge scripts so recurring workflows run without model calls; script-first execution with unconditional model-driven fallback, plan-time compilability analysis (conversational/interactive agents never plan-generated or compiled), workspace-authored plans, agent-owned scripts governed from the agent type's plan surface, human-gated self-improvement (requires-fix marking plus automatically recorded feedback, never unattended re-optimization), session-bound execution under the agent's identities and permissions, defect-driven script self-repair, optimization offered both as a one-shot action and as an interactive conversation, and auditable provenance and token-savings tracking. See [Software 3.0 Agent Framework](features/software-3-0-agent-framework.md)
- **Sandboxed Scripting & Model-Authored Composition** — Software 3.0 compiled workflows: sandboxed model-authored scripts seeded from a single audited safe-language baseline (with only documented guards added), a dedicated preconditioned Optimize action separate from Run that authors a separate optimized implementation plan (scripts-as-tools or fully-scripted zero-model mode; requires a successful reference run and a usable authoring model), a realistic bounded optimization goal, workspace-authored optimized plans, mandatory evidence review, replay-only verification with a single-use script-based live-test approval, an interactive optimization conversation on typed and conversational agent types (in-chat ask/decide, collapsed "What ran in this session" summary), requires-fix marking with automatically recorded feedback, unconditional fallback to the model-driven path, visible optimization failure reasons, a mock model layer for deterministic zero-cost testing, and trustworthy token-savings accounting. See [Sandboxed Scripting](features/sandboxed-scripting.md)
- **Agent Session Logs** — Full system instruction and user prompt captured for every agent run, visible in the UI for audit and traceability, with operator-approved live optimization script runs recorded and visibly distinct from replay verification work. See [Agent Session Logs](features/agent-session-logs.md).
- **Agent Runtime Security** — Service-segregation boundary enforcement, internal allowlist, and API key authentication for external agents. See [Agent Runtime Security](features/agent-runtime-security.md).
- **Agent A2A Communication and Slug Enforcement** — Dynamic agent-to-agent continuity, delegation governance, and slug-safe naming for routing-critical entities. See [Agent A2A Communication and Slug Enforcement](features/agent-a2a-communication-and-slug-enforcement.md).
- **Agent Data** — Filterable operator-facing module for browsing intermediate data saved by agents during execution, with full JSON inspection in a detail drawer. See [Agent Data](features/agent-data.md).
- **Agent Data Types** — Centralized registry of reusable typed output schemas; administrators define flat-typed fields (string, number, boolean, date, enum) and assign data types to non-conversational agent types for schema-validated outputs. See [Agent Data Types](features/agent-data-types.md).
- **Agent Gateway** — Lifecycle protocol, HTTP and MCP transports. See [Agent Gateway](features/agent-gateway.md).
- **Agent Outputs** — Schema-validated typed agent results with dedicated admin page (filtering by data type, date range, agent type, CSV export), `query_result` system tool for cross-session result analysis, and structured field-by-field rendering in execution logs. See [Agent Outputs](features/agent-outputs.md).
- **Agent Save Data and Historical Retrieval** — Separate intermediate data saves from final outputs; agents can save and query historical data and outputs across sessions; read-only result repository in the UI. See [Agent Save Data and Historical Retrieval](features/agent-save-data.md).
- **API Key Management** — API keys for third-party AI agents connecting to the MCP Hub; keys hashed at rest and bound to agent identity and role. See [API Key Management](features/api-key-management.md).
- **Control Center** — Governance management for agent policies, guardrail profiles, and operational oversight, including the embedded conversational assistant and its protected system-managed integration; one workspace-scoped authoring model for all plan and workflow authoring plus a separate optimizer model that falls back to it; and durable conversational turn supervision that survives the serving process with a persisted authoritative activity state. See [Control Center](features/control-center.md).
- **Control Center Assistant** — Built-in conversational assistant embedded in the Control Center that performs Agents-menu management (create/read/update of skills, SOPs, agent types, roles, identities, model configurations, schedules, data types, MCP Hub connections) on the signed-in user's behalf, within their own permissions, at full parity with the management forms for every resource family (every editable field), with self-correctable structured validation feedback, permission-denial transparency, preview-and-approve confirmation that stays durable across restarts and instance hand-offs, no deletion, resumable sessions with accurate persisted activity status, per-workspace model selection, and skill/tool binding and role-grant rules. See [Control Center Assistant](features/control-center-assistant.md)
- **Agent Runtime Monitor** — Live, interactive map of the running agent population: team-row layout by delegation depth, trigger-entity column with human attribution for schedule-triggered executions, whole-chain focus, tool-call routes through the Communication Hub and MCP servers, intervention alerts (including interventions awaiting human input that remain visible and answerable after a restart), inline termination, auto-fit canvas with zoom/pan/fullscreen, live server push updates, and recoverable filters. See [Agent Runtime Monitor](features/agent-runtime-monitor.md).
- **Communication Hub** — Message broker, WebSocket, session context, and agent-to-agent routing. See [Communication Hub](features/communication-hub.md).
