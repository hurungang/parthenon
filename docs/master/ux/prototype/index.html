👣 Walkthroughs
Four foundational design pillars presented in the showcase site's High-Level Architecture section.

🔌 SOP / Skill-Driven MCP Integration

Skills wrap one or more MCP tool calls into a named, permissionable unit. SOPs (Standard Operating Procedures) compose multiple Skills with sequencing logic and support agent-to-agent delegation. Each MCP server is registered with a unique slug; all its tools are synced under that namespace. Permissions are granted at the tool level — agents only see the tools their assigned Skills allow.

🛡️ Security & Permission Control

Agent Roles are permission sets granting access to specific SOPs and Skills. Roles resolve to a complete, deterministic set of allowed MCP tools at execution time. Agent identities are first-class OIDC principals in a dedicated agent realm, never sharing human credentials. Agents never hold identity tokens directly — tokens are injected per tool call by the Communication Hub.

⚙️ Three-Service Isolation

Control Center — sole database owner; manages CA, issues certificates, resolves permissions, maintains audit logs.
Communication Hub — central broker for UI↔agent and agent↔agent messaging; acts as Agent Gateway for session management.
Agent Runtime — the only service that executes agents (LangChain loop); authenticates via mTLS, never touches the database.
Cross-service calls use certificate-based mTLS; no service shares database credentials.

🪪 Dual Identity Support

User Realm — human accounts; OIDC login via Keycloak or Azure EntraID; standard OAuth2 flows.
Agent Realm — dedicated OIDC realm for AI agent identities; credentials stored encrypted, refreshed automatically.
Agent Types define the pairing of an agent identity, role, model config, system instruction, and I/O type. Each execution validates that the agent identity is still assigned to its declared role before proceeding.

🔐 Tool-Level Permission Control

Permissions are granted at the individual MCP tool level, not at the server level. Agent Roles define which Skills an agent can invoke; at runtime, those Skills resolve to an exact, deterministic allow-list of tools. Agents cannot call any tool outside that computed set — enforced by Control Center on every request.

SOP → Skill → Tool

📜 mTLS Certificate Authentication

Each Agent Runtime instance receives a short-lived agent-instance certificate (24-hour validity) issued by Control Center's built-in Certificate Authority. Internal services use longer-lived service certificates (30-day validity). All inter-service calls are mutually authenticated via mTLS — no shared secrets or API keys cross service boundaries.

24h agent-instance · 30d service

🔒 Token Isolation

Agent Runtime instances never hold identity tokens. When an agent needs to call an MCP tool, the Communication Hub resolves the correct OIDC token for the agent identity and injects it into that specific tool call — just-in-time and scoped. Agent-instance certificates are explicitly blocked from internal management endpoints.

Integrate MCP Server

  1. Register the MCP Server
    In Control Center → MCP Hub, supply a unique slug, server URL, and encrypted credentials.
  2. Sync & Verify Tools
    Query the MCP server's manifest and import all available tools under the slug namespace.
  3. Configure MCP Sessions
    Create named sessions that bind different identity credentials for varied OIDC contexts.
  4. Test Connectivity
    Use the built-in connection test to confirm the server is ready for Skill references.

Create Skill & SOP

  1. Define a Skill
    Select which MCP tools a Skill wraps — the smallest permissionable unit in Parthenon.
  2. Compose an SOP
    Combine multiple Skills in sequence with branching logic and agent-to-agent delegation steps.
  3. Review the Tool Allow-List
    The platform automatically resolves which MCP tools the SOP will expose at runtime.
  4. Test the SOP
    Simulate execution with a mock agent identity before exposing to production agents.

Create Agent Roles

  1. Create an Agent Role
    Select SOPs and Skills — the platform computes the complete transitive set of accessible MCP tools.
  2. Assign Agent Identities
    Attach OIDC agent identities via the many-to-many assignment panel. Each execution validates assignments.
  3. Audit the Role
    Review creation timestamps, identity assignments, and permission resolution history in the audit trail.

⚡ Non-Conversational Trigger

  1. Define Agent Type
    Set I/O to Non-Conversational, supply structured input schema and system instruction.
  2. Trigger via Schedule or API
    Use cron scheduler or Agent Gateway API with structured input payload.
  3. Retrieve Structured Result
    Agent persists output via built-in result-persistence tool. Query the Result Repository.

💬 Conversational Session

  1. Define Agent Type
    Set I/O to Conversational — agent maintains full conversation history across turns.
  2. Open a Session
    Web UI opens a WebSocket session via the Communication Hub. Stream responses in real time.
  3. Continue the Conversation
    Subsequent messages append to session history. Full tool call tracing in Execution Logs.

Execution Logs Viewer

Every agent run produces a rich, structured execution log visible in the Execution Log Viewer on the Agent Session page. Logs are captured before the first LLM call and span the entire observe-reason-act loop.

  • System context snapshot
    Full system instruction and user prompt captured at submission time for audit and traceability.
  • Span-based hierarchy
    Iterations, LLM calls, tool calls, and agent-to-agent delegations grouped into collapsible spans with timestamps and icons.
  • Tool call details
    Each MCP tool call shows input payload, raw response, and duration — expandable inline.
  • Raw log toggle
    Switch between structured user-friendly view and raw technical log for debugging.
  • OTEL integration
    Traces, metrics, and structured logs emitted to Prometheus, Jaeger, Loki, etc.
