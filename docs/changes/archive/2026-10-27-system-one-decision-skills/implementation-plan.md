# Implementation Plan: system-one-decision-skills

## Overview

This plan implements the System One decision capability as user-definable **decision tools** — not a skill type. Decision tools behave like Parthenon's built-in system tools: input/output contracts reference the platform's Agent Data Type Registry (`input_data_type_id` / `output_data_type_id` FKs — no inline schema storage, referenced types protected from deletion), an auto-generated tool description, availability to skills and agents through the existing system-tool pathway, and exposure as MCP tools with the canonical `decision____<name>` prefix via the shared tool-naming convention (`decision` added to `RESERVED_SERVER_NAMES`, mirrored in the frontend `toolNaming.ts`). The provider base URL is preset to `https://api.typesafe.ai/v1` with a Test-connection endpoint; Decision Tools administration lives under the Agent module; the authoring form offers guided state mapping (input-type-driven property selectors, backtick state-path auto-detection) and an AI generation button reusing `workflow_authoring_service`; saved decision tools appear in the tool registry listing when authoring skills, like system tools. Work spans reverting the decision-skill code (Skill model, schemas, API, executor, skill editor), new tenant-contained DB entities + migration (tool names unique per tenant), the encrypted System One provider configuration, the decision tool registry and execution engine in Control Center, MCP bridge registration, frontend admin UI, and full test coverage including tenant isolation.
