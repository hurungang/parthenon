Optimization mode — interactive optimization on the agent itself

Optimization is no longer a fire-and-forget command. Open a conversation from an agent type's Optimized Plan tab, watch the agent work in optimization mode, answer its question when replay can't prove a script, and approve one precisely described live test — once. Replay stays the default; every live operation needs your explicit approval, and denial — or a request left unanswered until it expires — keeps the session replay-only. The conversation runs as this agent — same identity, same permissions — so there is no separate optimizer agent. Conversational agents get the same conversation, opened from the same tab.

⚠️
This workspace has no usable optimizer model. Optimization conversations cannot start until one is available. Choose an optimizer model — or a plan authoring model for it to inherit.
1
Entry point, bound to one agent type
The Optimized Plan tab offers Talk to optimizer for that agent type only — the scope is shown on the surface.
2
Watch the optimizer work
Its steps and the information it looked at are visible — expandable, never a blank spinner.
3
Ask & decide in the chat
The optimizer asks when it can't verify. Options plus a free-text reply; input blocks until you answer.
4
Live test — the saved script, once
The card names the saved script version it wants to run and lists the tools it will call as information. Approving runs the whole script once — not the calls individually.
5
Deny → replay-only safe stop
Denying runs nothing. The plan lands in needs_feedback with the specific ask and your options.
6
A dedicated optimizer model
Workspace-scoped, used for the optimization conversation, inheriting the plan authoring model when unset.
7
Audit — replay vs live
A small what ran indicator, chat record and history rows tell replay work from an approved live run.
8
Scope is enforced, not just asked
Another agent type's plan, workspace settings or a delete request are declined and nothing changes.
9
No answer → the request expires
An unanswered live-test request closes after a bounded wait. Nothing runs, the session stays replay-only, and it is not retried.

Optimizer Model

🏢 Applies to this workspace only
The model that powers the optimization-mode conversation — the chat that refines an optimized plan for one agent type. That conversation runs as the agent itself, with the agent's own identity and permissions; this is not a runtime model and it never changes how an agent runs.
💬
The optimization conversation
Every optimization-mode conversation in this workspace uses this model — its questions, its reasoning about the log, and the script refinement it proposes.
🔁
Defaults to your plan authoring model
Leave it unset and optimization uses this workspace's Agent Plan Authoring Model. One editor, no second setting to keep in sync.
🧱
Workspace boundary
Changing it affects subsequent optimization in this workspace only. Other workspaces keep their own choice.
Only models enabled in this workspace's approved catalogue can be chosen. The optimizer never uses the agent type's runtime model unless that model was explicitly chosen here.
🔒
Replay-only verification, single-use live-test approval and the script lifecycle are unchanged by this choice — it decides which model thinks, not what is allowed.

Agent Plan Authoring Model

🏢 Applies to this workspace only
The model that authors implementation plans and Skill/SOP workflows — and the fallback for the optimizer when no optimizer model is chosen.
One setting governs every authoring surface. A higher-end model is recommended; any enabled model can be saved.
🏢 Workspace scope. Both choices apply to the current workspace only — changing them here never affects another workspace. When multi-tenancy is off, the deployment's single default workspace uses these settings.
