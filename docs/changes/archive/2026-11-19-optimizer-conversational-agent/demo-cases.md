## Grep Patterns
- Conversational optimizer — conversation journey (mocked) > typed agent: entry → scoped chat → single status indicator → plan refresh without a reload
- Conversational optimizer — conversation journey (mocked) > conversational agent: same entry, informational empty state, no work started
- Conversational optimizer — conversation journey (mocked) > in-chat ask/decide: the question pauses the turn and is answered once
- Conversational optimizer — conversation journey (mocked) > an out-of-scope request is declined in the conversation with zero writes
- Conversational optimizer — conversation journey (mocked) > a business conversation on the same agent type keeps the ordinary chat
- Live-test approval — approve runs the approved script once > review script → approve → running → executed run record → plan ready
- Live-test approval — approve runs the approved script once > deny runs nothing, keeps replay-only and does not retry
- Live-test approval — approve runs the approved script once > expiry is a distinct terminal state — nothing ran and no retry
- System Config — optimizer model (workspace-scoped) > a stale saved value stays visible, blocks Save, and can be re-selected
- Optimizer model missing — entry annotated, chat blocked, System Config path > the Optimized Plan entry explains the reason and the chat blocks on the model

## Scenario Details
| # | Feature | What it Shows | Spec File | Test Name |
|---|---|---|---|---|
| 1 | Conversational optimization on a typed agent (entry → chat → single status indicator → plan refresh) | The Optimized Plan tab offers "Talk to optimizer" tied to this one agent (identity parity + the optimizer model disclosed, existing Optimize/retire actions kept). Opening it starts no work; the first message creates the subject-only optimization session, the chat shows only the compact, default-collapsed "What ran in this session" bar (replay-only default) and its expanded scope/identity detail, the streaming turn shows exactly ONE processing indicator (the normal chat-status indicator — the old folded "optimizer activity" block is gone, and it disappears once the turn is terminal), and the finished turn refreshes the plan in place — no reload, no one-shot Optimize call. | `e2e/tests/agent-optimizer-conversation.spec.ts` | typed agent: entry → scoped chat → single status indicator → plan refresh without a reload |
| 2 | Conversational agent with no plan (informational, not hidden) | Same entry on a conversational agent (the old restriction is gone), annotated with scope and "inherits the plan-authoring model". A missing optimized plan is an informational empty state, and opening the chat creates no session, no plan generation and no live request — nothing is fabricated. | `e2e/tests/agent-optimizer-conversation.spec.ts` | conversational agent: same entry, informational empty state, no work started |
| 3 | In-chat ask/decide (lightweight, not the interventions dashboard) | The optimizer asks a choice question inline; the composer blocks until the operator answers, exactly one answer frame is sent from the chat, and the answer stays in the conversation record as a resolved bubble before the turn continues. | `e2e/tests/agent-optimizer-conversation.spec.ts` | in-chat ask/decide: the question pauses the turn and is answered once |
| 4 | Scope inherent — out-of-scope request refused with zero writes | A prompt-injected request to read another agent's scripts and delete its plan is refused in-channel with the standard out-of-scope explanation; no turn, plan, approval or other agent type's endpoints are touched. | `e2e/tests/agent-optimizer-conversation.spec.ts` | an out-of-scope request is declined in the conversation with zero writes |
| 5 | Mode containment — business conversation unaffected | Starting a normal business chat on the same agent type keeps the ordinary composer and placeholder, shows none of the optimization chrome (mode chip, "What ran in this session" bar, model alert), creates a business session (never the optimization endpoint) and never reads the optimizer model or live-test ledger. | `e2e/tests/agent-optimizer-conversation.spec.ts` | a business conversation on the same agent type keeps the ordinary chat |
| 6 | Live-test approval — one end-to-end run of the SAVED SCRIPT, once (with replay-vs-live audit) | The approval card names the saved script version the optimizer wants to run (the script is the unit of approval) and shows the server-derived tool-call preview as information ("It will call: …"), stating the run is one end-to-end execution as this agent, once, not remembered. Approve sends one decision; the card collapses by decision and moves pending → running → then shows a one-line executed summary that expands to the script run record (output, telemetry, per-`tools.call` outcomes) — inline in the transcript at its decision position (after the request, before the assistant's final summary), and the "What ran in this session" bar's audit detail distinguishes 1 replay verification from 2 approved live operations (single use) while the refinement lands a ready plan without a reload. A later need starts a brand-new script request with a new approval. | `e2e/tests/agent-optimizer-live-test-approval.spec.ts` | review script → approve → running → executed run record → plan ready |
| 7 | Live-test deny — nothing runs, stays replay-only, no retry | Deny sends no approval, the card collapses to a read-only `denied` summary with no further actions, the "What ran in this session" bar and audit detail stay replay-only (zero live operations), and the turn ends in a bounded "what is missing" stop without a second script request. | `e2e/tests/agent-optimizer-live-test-approval.spec.ts` | deny runs nothing, keeps replay-only and does not retry |
| 8 | Live-test expiry — distinct terminal state, no retry | An unanswered request past its answer window is closed as `expired` (distinct collapsed chip and copy, preview kept for audit), the script never ran, no decision frame is ever sent, and replay-only remains in force with no retry. | `e2e/tests/agent-optimizer-live-test-approval.spec.ts` | expiry is a distinct terminal state — nothing ran and no retry |
| 9 | Optimizer Model configuration — stale value stays visible and blocks Save | System Config shows a saved model that is no longer enabled as a disabled "no longer available" option plus a re-select reminder; Save is blocked until a valid catalogue model is re-selected, then exactly one PUT persists the new choice and the reminder clears — the stale value is never auto-cleared or silently substituted. | `e2e/tests/agent-optimizer-model-config.spec.ts` | a stale saved value stays visible, blocks Save, and can be re-selected |
| 10 | Optimizer model unavailable — fail-closed entry, blocked chat, System Config path | With no usable optimizer model the entry is annotated with the shared reason and a System Config shortcut, the conversation still opens but shows the model alert with a disabled composer (no work can start), and the shortcut lands directly on the section showing the unset reminder — no conversation is ever created. | `e2e/tests/agent-optimizer-model-config.spec.ts` | the Optimized Plan entry explains the reason and the chat blocks on the model |
