## FIX-20260521-192300

**Created:** 2026-05-21T19:23:00Z
**Status:** Completed
**Issue:** Conversational agents are executing in Communication Hub instead of Agent Runtime, causing conversation logs to be emitted from the wrong service boundary and violating runtime ownership expectations.

### Observed Behavior
Conversation WebSocket requests are handled and executed in the Communication Hub process. The conversational execution loop and related logs are emitted in Communication Hub logs instead of Agent Runtime logs.

### Expected Behavior
All agent execution, including conversational agent turns initiated through WebSocket, should run in Agent Runtime service. Communication Hub should broker/proxy transport only, while execution logs should be generated by Agent Runtime.

### Analysis
- **Affected components:**
  - `backend/app/api/ws/chat.py`
  - `backend/app/communication_hub/main.py`
  - `backend/app/agent_runtime/main.py`
  - `backend/app/agent_runtime/api/` (new/updated internal conversation execution endpoint expected)
  - `backend/app/services/agents/runtime_executor.py`
  - `docs/config.yaml`
  - `.github/copilot-instructions.md`
- **Root cause hypothesis:** Conversation WebSocket router is mounted in Communication Hub and invokes `AgentRuntimeExecutor.execute_conversation_turn()` in-process, bypassing Agent Runtime service boundary.
- **Documentation impact:**
  - Update configuration-level architecture rule in `docs/config.yaml` to mark runtime service ownership as top-priority behavior.
  - Update `.github/copilot-instructions.md` to require always checking `docs/config.yaml` for top priority rules before implementation.

### Implementation Details
- Communication Hub chat flow no longer executes conversation turns in-process.
- `backend/app/api/ws/chat.py` now delegates conversation turn execution to Agent Runtime through `POST /internal/conversation/turn`.
- Agent Runtime now exposes `POST /internal/conversation/turn` in `backend/app/agent_runtime/api/conversation.py` and executes the existing `AgentRuntimeExecutor.execute_conversation_turn` there.
- Agent Runtime app registration updated in `backend/app/agent_runtime/main.py` to include the new conversation router.
