# Implementation Plan: separate-optimization-from-execution

## Overview

Separate optimization from execution: a normal **Run** keeps the agent's own system/skill instructions and never doubles as an optimization mission, while a distinct, preconditioned **Optimize** action triggers a dedicated, bounded optimization execution that authors a `ready` optimized plan (or stops at `needs_feedback` with no dead loop). A later execution that falls back to the LLM path because of the optimized plan marks that plan `requires_fix` and appends execution-derived feedback, surfacing a human-in-the-loop alert with a re-optimize path that carries the prior plan plus feedback.

**Refinement (authoring model, explicit-only generation, conversational exclusion):** plan authoring (implementation **and** optimization plans) runs on the workspace's single tenant-level authoring model (`TenantSetting.workflow_generation_model_id`) — never the agent's runtime model, never a first-available/default fallback. Implementation-plan generation happens only on an explicit request (the automatic generation scheduled on agent create/update is removed), the optimization run itself executes on the authoring model (internal agent-context returns the authoring model + resolved config id for `__command` runs), and both generation paths are gated on *authoring model configured & enabled* **and** *non-conversational agent*. System Config explains the three uses, recommends a larger model (advisory), and reminds when unset — all tenant-scoped.
