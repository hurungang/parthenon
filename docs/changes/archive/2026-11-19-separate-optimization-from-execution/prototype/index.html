Separate Optimization from Execution

Running an agent now only runs the agent — it never turns into an optimization mission. Optimization is its own explicit, preconditioned action that stays realistic, bounded, and human-gated. Plans are authored only when you ask, by one workspace-level authoring model. This prototype walks the 11 key flows below.

⚠️
No plan authoring model configured for this workspace. Plan generation and ✦ Optimize are unavailable until an administrator chooses one — no other model is used as a fallback.
1
Run is execution-only
The Run dialog carries the agent's own task — no "run with optimization" toggle.
2
Separate Optimize action
A dedicated ✦ Optimize sits beside ▶ Run — a separate action, not a run option.
3
Precondition: success first
Optimize is disabled until one successful run. Click to see the explanation.
4
Optimization run → ready
Optimize authors & verifies scripts from the latest run, then lands "ready".
5
Bounded: no confidence
No high confidence → stops with needs_feedback. Never loops forever.
6
Plan flagged "requires fix"
A later run falls back to the model path → plan flagged + alert shown.
7
Re-optimize w/ feedback
Re-optimize carries the prior plan + auto feedback; manual feedback still works.
8
System Config — authoring model
One workspace model authors Skill/SOP workflows, implementation plans and optimization plans. A larger model is recommended — smaller ones can still be saved.
9
Plans only on request
Saving or creating an agent never authors a plan. Plan Preview shows "no plan yet" with an explicit ✨ Generate plan.
10
No model → authoring blocked
Clear the model, then try to generate a plan or optimize: both are blocked with a pointer to System Config.
11
Conversational agents excluded
Plan generation and optimization are unavailable for conversational agents, with a plain explanation.

Workspace Settings
⚠️

Agent Plan Authoring Model

🏢 Applies to this workspace only
One model per workspace authors everything the platform generates on your behalf:
🧭
Skill / SOP workflow generation
Drafts the workflow when you generate a Skill or SOP from the tool catalogue.
📋
Implementation-plan generation
Writes the agent's plan when you explicitly ask for it from Plan Preview.
✦
Optimization-plan generation
Authors the optimized plan when you trigger ✦ Optimize on an agent.
💡
We recommend a larger, higher-end model. Plan authoring quality depends on this choice — a small, cheap model produces weaker plans. This is advice, not a restriction: any enabled model can be saved. Agents keep their own runtime model, which is a separate choice and is never used to author plans.
Only models enabled in this workspace's model catalogue can be chosen. One setting governs every authoring surface — there is no second setting to keep in sync.
🏢 Workspace scope. This choice applies to the current workspace only — changing it here never affects plan generation in another workspace. When multi-tenancy is off, the deployment's single default workspace uses this setting.
