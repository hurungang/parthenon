🔍 How Content-Type Detection Works in Chat

Step 1

When an agent response is received, the renderer checks if the content contains HTML tags (<table>, <h3>, <ul>, etc.)

Step 2

If HTML tags are detected → the content is sanitised and rendered as rich HTML inline in the chat bubble, preserving tables, lists, and styling.

Step 3

If no HTML tags are detected → the content renders as plain text with preserved whitespace and line breaks, exactly as it does today.

A Maximize button appears on every agent message, allowing operators to expand any output into a focused full-view overlay.

🔍 How Content-Type Detection Works in Execution Detail

Step 1

The execution detail renderer checks the output type. Typed outputs follow their existing field-by-field path — no change.

Step 2

For auto outputs, the content is scanned for HTML tags before rendering.

Step 3

If HTML detected → content is sanitised and rendered directly as HTML, bypassing markdown conversion.

Step 4

If no HTML detected → content goes through standard markdown-to-HTML conversion as before.

A Maximize button on the result toolbar opens the full rendered output in an overlay — same interaction pattern as in chat.
