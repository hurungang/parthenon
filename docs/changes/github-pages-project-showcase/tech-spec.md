## API Changes

**None.** This is a fully static site with no backend integration, no API calls, and no dynamic data. The site requires no server-side runtime.

## Data Access Patterns

**None.** All content is hardcoded in `site/index.html`. There are no database queries, no API fetches, and no user authentication. The Mermaid diagram is rendered client-side from inline source text bundled into the output HTML.

## Build Configuration

### `site/vite.config.ts`

```ts
import { defineConfig } from 'vite'

export default defineConfig({
  base: './',          // relative base so GitHub Pages works at any subpath
  build: {
    outDir: '../docs/site', // output to repo-root docs/site/
    emptyOutDir: true, // clean docs/site/ on each build to avoid stale assets
  },
})
```

**Key decisions:**

- `base: './'` — GitHub Pages may serve the site at `/<repo-name>/` rather than `/`. A relative base ensures all asset references work regardless of the Pages URL structure.
- `outDir: '../docs/site'` — the site output is isolated under `docs/site/` so existing product documentation in `docs/` is not overwritten by Vite builds.
- `emptyOutDir: true` — prevents accumulation of old hashed asset bundles across builds.

### `site/package.json` dependencies

| Package | Role |
|---------|------|
| `vite` | Build tool and dev server |
| `typescript` | TypeScript compiler |
| `mermaid` | Diagram rendering (bundled, no CDN) |

Scripts:
- `"dev": "vite"` — local development server
- `"build": "vite build"` — production build → `docs/site/`
- `"preview": "vite preview"` — preview built output locally

## GitHub Actions Pipeline Design

### Workflow file: `.github/workflows/deploy-github-pages.yml`

**Trigger:** `push` to the `main` branch, filtered to `site/**` path changes. This prevents unnecessary deployments when only backend or frontend code changes.

**Permissions required:**
- `contents: read` — checkout repository
- `pages: write` — upload Pages artifact
- `id-token: write` — OIDC token for Pages deployment (required by `actions/deploy-pages`)

**Pipeline structure:**

```
┌─────────────────────────────────────────────┐
│  Job: build                                  │
│  runs-on: ubuntu-latest                      │
│                                              │
│  1. actions/checkout@v4                      │
│  2. actions/setup-node@v4 (node 20)          │
│  3. npm ci  (working-directory: site)        │
│  4. npm run build  (working-directory: site) │
│  5. actions/upload-pages-artifact@v3         │
│     path: docs/site                          │
└──────────────────┬──────────────────────────┘
                   │ needs: build
┌──────────────────▼──────────────────────────┐
│  Job: deploy                                 │
│  environment: github-pages                   │
│  url: ${{ steps.deployment.outputs.page_url }}│
│                                              │
│  1. actions/deploy-pages@v4                  │
└─────────────────────────────────────────────┘
```

**One-time manual prerequisite:** In repository Settings → Pages, set Source to **"GitHub Actions"**. Without this, the `deploy-pages` action will fail.

**No external secrets required.** The workflow uses only GitHub-provided OIDC tokens for Pages deployment.

## Placeholder Image Strategy

Each demo tab panel requires one screenshot placeholder image. Placeholders are committed SVG files in `site/public/images/` so they are static assets (no runtime generation needed).

### SVG spec per placeholder

| Property | Value |
|----------|-------|
| Dimensions | 800 × 500 px (`viewBox="0 0 800 500"`) |
| Background fill | `#161d35` (matches `--bg-card` token) |
| Border | Dashed rectangle, stroke `#7c5cfc` (accent), `stroke-dasharray="8 4"`, `stroke-width="2"` |
| Camera emoji | Centered at ~(400, 180), `font-size="48"` |
| Primary label | Screenshot name, `fill="#f0f2ff"` (text-primary), `font-size="20"`, `font-weight="600"` |
| Caption | "Replace with actual screenshot", `fill="#5c6b8a"` (text-muted), `font-size="14"`, italic |
| Filename label | Monospace filename, `fill="#a285fd"` (accent-light), `font-size="12"`, `font-family="monospace"` |

### Placeholder inventory

| File | Tab | Primary label |
|------|-----|---------------|
| `placeholder-mcp.svg` | Tab 1 | MCP Server Registration UI |
| `placeholder-skill-sop.svg` | Tab 2 | Skill & SOP Configuration UI |
| `placeholder-agent-roles.svg` | Tab 3 | Agent Roles Management UI |
| `placeholder-agent-trigger.svg` | Tab 4 | Agent Types & Trigger UI |
| `placeholder-exec-logs.svg` | Tab 5 | Execution Logs Viewer |

In `index.html`, each placeholder is an `<img>` tag:

```html
<img
  src="/images/placeholder-mcp.svg"
  alt="MCP Server Registration UI — screenshot placeholder"
  class="demo-screenshot"
/>
```

CSS class:
```css
.demo-screenshot {
  width: 100%;
  border-radius: var(--radius-md);
  display: block;
}
```
